# AXIOM — AI, который узнаёт тебя и строит поступление вокруг тебя

**LOCUS Startup Hackathon 2026 · Кейс 02 «Персональный маршрут поступления»**

AXIOM — это AI-сервис поступления, который не выдаёт список университетов, а **разговаривает** с абитуриентом, **запоминает** важное о нём (интересы, бюджет, IELTS, страну, приоритеты, ограничения) и строит **персональный маршрут**: рекомендации → сравнение → сценарии «а что если» → пошаговый план → конкретный следующий шаг.

Цепочка продукта: **разговор → память → персональные вузы → сравнение → What If → маршрут → следующий шаг.**

---

## 1. Задача и решение

Абитуриенту нужен маршрут, а не ещё один список: десятки решений, разрозненная информация, непонятно, что подходит именно тебе и что делать сейчас.

**Решение AXIOM:**

| Этап кейса | Что сделано в AXIOM | Маршрут |
| --- | --- | --- |
| 1. Вход | Лендинг с ценностью и мгновенным демо-профилем | `/` |
| 2. Профиль | AI-интервью голосом или текстом + ручная анкета | `/interview` |
| 3. Диагностика | Резюме профиля: цель, сильные стороны, ограничения, полнота | `/diagnosis` |
| 4. Рекомендации | 45 программ в 15 странах с оценкой соответствия и объяснением «почему подходит» | `/recommendations` |
| 5. Сравнение | 2–3 программы рядом, лучшие значения подсвечены, включая полную стоимость обучения | `/compare` |
| 6. Roadmap | Экзамены, документы, дедлайны, активности под выбранную цель | `/roadmap` |
| 7. Следующее действие | Один выделенный ближайший шаг + прогресс по категориям | `/roadmap` |

**Ключевая фишка — Memory.** Пользователь говорит «хочу Европу и бюджет до $15k» — AXIOM подсвечивает эти слова прямо в его сообщении и превращает их в чипы памяти (факт + цитата + уверенность). Любой факт можно изменить или удалить, и вся выдача (рейтинг, объяснения, маршрут) мгновенно перестраивается. Реплика «стипендия теперь важнее страны» меняет приоритеты — и топ рекомендаций меняется на глазах.

## 2. Проверочный сценарий для жюри

1. Открой прод-ссылку → нажми **«Посмотреть демо»** (или «Начать интервью», чтобы пройти путь с нуля).
2. Отвечай на вопросы (голосом в Chrome или текстом). После каждого ответа смотри направо: слова подсвечиваются, появляются чипы **памяти**.
3. **Ключевой момент.** Измени факт: в чипе «Интересы» нажми карандаш → поставь `Дизайн`. Открой «Рекомендации» — топ пересобран, первая программа другая (топ-5 расходится с прежним на 66%). Одно слово в памяти переписало всю выдачу.
4. Теперь измени чип «Бюджет» на `до $6 000`. Здесь порядок меняется слабее — верхние строчки держат программы с полной стипендией, для которых бюджет не решает, — зато у остальных появляются пометки «превышает бюджет» с процентом. Это тоже честный ответ: сервис не делает вид, что деньги решают всё.
5. «Диагностика» — резюме профиля, сильные стороны и ограничения, полнота профиля.
6. «Рекомендации» — у каждой программы: соответствие, «почему подходит» (со ссылкой на факты), «чего не хватает», дедлайн со стипендией и источник. Добавь 2–3 в сравнение.
7. «Сравнение» — таблица параметров, зелёным подсвечено лучшее. Нажми «Сделать целью».
8. «What If» — пресет **«Стипендия важнее страны»**: рейтинг перестраивается с анимацией, в сводке — что и на сколько поднялось/выпало. Подвигай бюджет/IELTS слайдерами.
9. «Маршрут» — цель, следующий шаг, чек-лист по категориям. Отметь шаг выполненным — прогресс обновится. Прогресс и память сохраняются после перезагрузки страницы.
10. Проверь мобильную версию: шапка показывает «Шаг N из 6», меню сворачивается, таблица сравнения скроллится.

Изменение интересов, страны, IELTS или приоритета **заметно** меняет рекомендации и маршрут — это основной критерий кейса. Насколько заметно — измеряется: `npm run demo` прогоняет этот сценарий целиком (75 проверок) и проверяет, что демо-правка расходится с прежним топ-5 не меньше чем на 30%. Сценарий, где жюри правит факт и ничего не происходит, хуже отсутствия сценария.

## 4. Архитектура

```
shared/                        ← единый источник правды
├── types.ts                     типы MemoryFact, Program, Recommendation…
├── contract.md                  описание API
├── data/programs.json           45 программ, 15 стран (демо-данные + источники)
└── engine/                      чистый TypeScript без зависимостей
    ├── extract.ts               извлечение фактов из речи/текста
    ├── recommend.ts             скоринг и ранжирование программ
    ├── whatif.ts                пересчёт рейтинга и diff «до/после»
    ├── roadmap.ts               генерация маршрута под цель
    ├── diagnosis.ts             резюме профиля
    ├── interview.ts             вопросы интервью и реплики AXIOM
    ├── profile.ts               доступ к фактам памяти
    └── format.ts                форматирование денег/дат (RU)

      npm run sync  (копирует shared → оба проекта)
      ├──────────────┐
frontend/lib/shared   backend/src/shared
```

**Почему так:** весь пользовательский путь работает **на встроенном движке без сети** — демо не падает, если бэкенд недоступен или у жюри плохой Wi-Fi. Бэкенд отдаёт тот же движок по HTTP (для интеграций) и добавляет опциональное LLM-обогащение. Один источник правды + скрипт синхронизации = никаких расхождений между фронтом и бэком.

**Как принимаются решения:**

- **Скоринг** — детерминированные правила (бюджет, страна, IELTS, интересы, стипендия, сроки). Вес каждого критерия виден, объяснения ссылаются на конкретные факты памяти. Никаких «магических» рекомендаций.
- **Считается стоимость всей программы, а не только года.** Бюджет называют за год, но платить придётся за все годы: четырёхлетняя за $11 000 обходится дороже трёхлетней за $13 000. Раньше движок считал их равными. Теперь длительность входит в оценку и полная сумма стоит в объяснении — кроме программ с полной стипендией, где лишний год семье ничего не стоит.
- **Числа, сказанные словами, понимаются.** Web Speech API возвращает «пятнадцать тысяч» вместо «15000» и «шесть с половиной» вместо «6.5» — без разбора числительных голосовой ввод терял бюджет, IELTS, средний балл и класс, то есть почти весь профиль. Нормализация идёт одной предобработкой (`numerals.ts`), поэтому остальные правила работают с привычными цифрами и не усложняются.
- **Разговор — это способ передумать.** Память различает «дополни» и «замени»: «ещё рассматриваю Финляндию» расширяет список стран, а «хочу только Германию, а не всю Европу» схлопывает его до сказанного и исключает названное с отрицанием. Без этого сервис копил противоположное: три уточнения подряд превращались в «Европа; Германия; Польша». Перечисление при этом не ломается — «не только IT, но и дизайн» добавляет оба.
- **Превышение бюджета никогда не скрывается.** Дороже бюджета — только с явной пометкой и процентом превышения. Раньше предупреждение о деньгах было «причиной» и обрезалось по весу вместе с остальными: программа за $10 300 при бюджете $7 000 выглядела в карточке как обычный вариант.
- **Недостижимое стоит ниже достижимого.** Порог IELTS и среднего балла — условие приёма, а не предпочтение: как вес он стоил ~6 баллов из 100, и программа с пометкой «у тебя 64% при пороге 80%» всё равно оказывалась первой. Отборные программы по-прежнему видны, но ниже тех, куда реально можно поступить.
- **Ограничение — это условие, а не пожелание.** Фраза «не хочу учить новый язык» или «без стипендии не потяну» разбирается в признаки и множит итоговую оценку нарушивших программ, а не сдвигает её на пару баллов. Иначе немецкие программы оставались бы в топе у человека, который прямо сказал, что язык учить не будет. Знание языка снимает ограничение: «знаю немецкий» возвращает немецкоязычные программы наверх и превращает пробел в причину.
- **Срок старта двигает маршрут.** Дедлайны в датасете указаны для ближайшего набора; если человек планирует поступление позже, весь план сдвигается на нужное число лет.
- **Совпадение направления оценивается по покрытию, а не «да/нет».** Интерес «маркетинг» раскрывается в теги `marketing` + `business`; программа, закрывающая оба, обходит ту, что закрывает только общий `business`. Иначе на запрос «маркетинг» первым выходил International Business с полной стипендией, а профильные маркетинговые программы оставались ниже.
- **Память помнит прошлые значения и объясняет последствия.** `mergeFacts` больше не затирает факт молча: прежнее значение уходит в `history`, а правка возвращает diff. Поэтому на изменение бюджета сервис отвечает не новым списком, а фразой «Бюджет в год: до $15 000 → до $10 000. 11 программ вышло за бюджет (3 → 14)». Если порядок не изменился, но оценки пересчитались — это тоже сказано вслух.
- **Средний балл нормализуется по шкале.** «GPA 3.8» — это 4-балльная шкала (95%), «средний балл 3.8» — 5-балльная (76%). Движок выводит шкалу из формулировки, уважает явную («8 из 10»), и сравнивает все баллы в процентах от максимума — иначе отличник по 4-балльной проигрывал бы середняку по 5-балльной. У каждой программы есть порог `gpaMinPercent`, поэтому балл влияет на рейтинг, на объяснения и на маршрут (появляется шаг «подтянуть балл»).
- **Приоритет из памяти меняет сами веса.** Фраза «стипендия важнее страны» сохраняется как факт `priority` и через `PRIORITY_WEIGHT_MULTIPLIERS` поднимает вес критерия «стипендия» и опускает вес «страны» — рейтинг на `/recommendations` перестраивается сразу, ещё до экрана What If. Ответ API возвращает применённые `weights`, `appliedPriority` и человекочитаемый `priorityNote`, поэтому решение можно проверить, а не принять на веру.
- **Извлечение фактов** — регулярные правила (мгновенно, работает офлайн) + опционально LLM. Модели разрешено ровно одно: **добавить то, чего правила не нашли**. Переписать надёжно извлечённое она не может, факт без опоры на текст отбрасывается (цитата проверяется по реплике — по ней же строится подсветка), страна и направление принимаются только из словаря движка, числа — только в допустимых диапазонах. Каждое отклонение попадает в лог с причиной. Раньше ответ модели сливался поверх правил, и правдоподобная галлюцинация, прошедшая JSON-схему, молча меняла бюджет, IELTS и средний балл.
- **What If** — те же правила с изменёнными весами, плюс diff-анализ топ-5 (кто поднялся, кто выпал). Сводка всегда называет, **что именно** изменили («Бюджет $15 000 → $10 000», «IELTS 6.0 → 7.0»), а не только следствие — иначе разные сценарии читались одинаково. Если ничего не сдвинулось, сервис объясняет почему, опираясь на данные («твой топ уже состоит из программ с полным покрытием»), а не отписывается «рейтинг стабилен». Каждый пресет проверяется тестом на то, что он реально меняет топ-5 хотя бы на 10%.
- **Диагностика считает в рамках сказанного.** «Бюджет покрывает 33 из 45 программ» ничего не значит человеку, который хочет медицину: по его направлению их три, а по бюджету и IELTS проходит одна. Теперь все цифры считаются от выборки по направлению и географии и так и подписаны, а если по всем условиям сразу не проходит почти ничего — это сказано прямо, с советом, что смягчить. Покрытие меньше половины попадает в ограничения, а не в сильные стороны: «покрывает 0 из 3» в списке достижений читалось издевательством.
- **Маршрут** — шаблоны категорий, параметризованные профилем и дедлайнами цели (например, нет IELTS → появляется «подготовка» и «сдать», балла не хватает → «поднять и пересдать»). Маршрут знает сегодняшнюю дату: шаги, чей обычный срок уже прошёл, помечаются «как можно скорее», а не показывают месяц из прошлого. Рядом со следующим шагом стоит честная оценка запаса времени — «до подачи 4 месяца, а спокойный график требует восьми». Когда набор проходит целиком, маршрут сам переезжает на следующий.
- **Интервью адаптивное, а не анкета.** Следующий вопрос выбирается по состоянию памяти: сначала знакомство, затем противоречия, затем пробел с максимальной пользой. «Польза» считается, а не назначается: движок подставляет правдоподобные ответы и измеряет, насколько переставится топ-5. Поэтому вопрос про страну опережает вопрос про GPA — у GPA влияние честно равно нулю, он пока не участвует в скоринге.
- **Противоречия ищутся по данным.** «Бюджет $9k и Нидерланды» → AXIOM отвечает «дешевле $22 800 там ничего нет, что двигаем?». Проверяются бюджет против географии, IELTS против порогов, отказ учить язык против неанглоязычных стран, интересы против географии, старт в прошлом.

## 5. Запуск локально

Требования: Node.js 20+.

```bash
# 0) корень репозитория — разложить shared по проектам
npm run sync

# 1) backend (необязателен — фронт работает и без него)
cd backend
npm install
cp .env.example .env          # ключи LLM опциональны
npm run dev                   # http://localhost:8787
npm run selftest              # 300 авто-проверок движка
npm run e2e                   # 54 проверки API по HTTP
npm run quality               # качество рекомендаций на 13 профилях
npm run demo                  # демо-сценарий README шаг за шагом
npm run verify                # всё сразу

# 2) frontend
cd ../frontend
npm install
cp .env.example .env.local    # NEXT_PUBLIC_API_URL=http://localhost:8787 (или пусто)
npm run dev                   # http://localhost:3000
npm run build                 # prod-сборка
```

После правок в `shared/` всегда выполняй `npm run sync` из корня и коммить изменения. Забыть не страшно: `npm run verify` начинается со сверки копий с источником правды и падает с указанием разошедшихся файлов. Это важнее, чем кажется, — при расхождении тесты остаются зелёными, а демо считает по старым правилам.

## 6. API (бэкенд)

Полный контракт — `shared/contract.md`. Кратко:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | статус + режим движка (rules / llm) |
| GET | `/metrics` | счётчики запросов, задержки p50/p95, состояние LLM |
| GET | `/programs` | датасет программ |
| POST | `/extract` | извлечь факты памяти из реплики |
| POST | `/recommend` | ранжировать программы под профиль |
| POST | `/whatif` | пересчитать рейтинг + diff |
| POST | `/roadmap` | построить маршрут под программу |
| POST | `/diagnose` | резюме профиля (опц. LLM) |
| POST | `/interview/next` | следующий вопрос интервью по состоянию памяти |
| POST | `/conflicts` | противоречия между фактами памяти |
| POST | `/memory/update` | обновить память + объяснение «что изменилось и к чему привело» |

Запросы валидируются zod-схемами. Ошибки возвращаются как `{ "error": "...", "requestId": "..." }`; тот же `requestId` уходит в заголовок `x-request-id` и в структурный лог, поэтому обращение пользователя связывается с конкретной строкой лога. Есть лимит запросов с IP (`RATE_LIMIT_PER_MIN`, по умолчанию 120/мин), корректное завершение по SIGTERM и кэш ответов LLM с повторными попытками.

## 7. AI и данные — честно

- **Правила — ядро.** Скоринг, What If, маршрут и диагностика детерминированы и проверяемы. Это сделано осознанно: критерий кейса — «точность и проверяемость», а не «побольше магии».
- **LLM — обогащение.** Если задан ключ (Gemini/OpenAI), модель дополняет извлечение фактов и пишет резюме диагностики. Ответы проверяются не только JSON-схемой, но и по смыслу: факт без цитаты из реплики, значение вне словаря движка или число вне диапазона отбрасываются, а перезаписать результат правил модель не может в принципе. При недоступности LLM сервис отвечает на правилах — интерфейс честно показывает режим («AI-резюме (LLM)» / «Резюме на правилах»).
- **Голос** — браузерный Web Speech API (Chrome/Edge, ru-RU). Распознавание отдаёт текст без пунктуации и часто числами-словами, поэтому извлечение фактов нормализует числительные перед разбором. Всегда есть текстовый ввод; в остальных браузерах сервис полностью работоспособен.
- **Данные вузов — демонстрационные.** Все 45 программ помечены в интерфейсе бейджем «Демо-данные», у каждой указан официальный источник (сайт вуза / Stipendium Hungaricum). Цифры приближены к реальным публичным данным, но **перед подачей их нужно сверять с официальными сайтами**.
- **Никаких гарантий.** «Соответствие» — это оценка по профилю, а не вероятность поступления; формулировка продублирована в интерфейсе.

## 11. Воспроизводимость проверки

```bash
# всё сразу: синхронизация shared, типы, движок, API, качество и демо-сценарий
cd backend && npm run verify

# движок: 300 авто-проверок (извлечение, скоринг, what-if, roadmap, диагностика)
cd backend && npm run selftest

# API по HTTP: 54 проверки (валидация, коды ошибок, заголовки, лимит, метрики)
cd backend && npm run e2e

# качество рекомендаций: 13 живых профилей (включая голосовой), порог 95%
cd backend && npm run quality

# демо-сценарий из раздела 2, шаг за шагом: 75 проверок
cd backend && npm run demo

# типы и сборка
cd backend && npm run typecheck
cd frontend && npm run typecheck && npm run build
```

Проверки покрывают: парсинг бюджета/IELTS/GPA с граничными случаями, слияние памяти, порядок и объяснения рекомендаций, влияние факта «приоритет» на веса и на сам порядок выдачи, реакцию рейтинга на смену приоритетов, выбор следующего вопроса интервью и расчёт его пользы, детекцию противоречий в памяти, шкалы среднего балла и его влияние на выдачу, историю фактов памяти и объяснение правок, целостность датасета и распознавание всех его стран и языков из речи, влияние ограничений и знания языка на выдачу, различение «дополни» и «замени» в речи, сдвиг маршрута под год старта, устойчивость к пустому, мусорному и очень длинному вводу, структуру и хронологию маршрута, полноту диагностики. Отдельная проверка следит, чтобы ни один из 11 фактов памяти не стал «мёртвым» — то есть не перестал влиять на рейтинг, маршрут или диагностику.

### Качество рекомендаций измеряется, а не оценивается на глаз

`npm run quality` прогоняет 13 профилей, сформулированных так, как говорят живые
абитуриенты («хочу стать врачом», «новый язык учить не хочу», «бюджет очень
маленький»), и проверяет 44 ожидания: топ соответствует направлению, бюджет
никогда не превышается молча, названные ограничения не нарушаются, у каждой
программы есть объяснение, у слабого профиля есть хотя бы один достижимый
вариант. Порог — 95%, текущий результат — 100%.

Там же измеряется **устойчивость рейтинга** — три числа, которые отвечают на
вопрос «а веса вы не подогнали?»:

| Что измеряем | Результат |
| --- | --- |
| Расхождение топ-5 при изменении любого веса на ±20% | 7% в среднем, 38% максимум |
| Расхождение топ-5 при мелкой правке профиля ($15 000 → $15 100, IELTS 6.0 → 6.1) | 0% |
| Максимальный скачок оценки при плавном изменении бюджета | 1 балл |

Первое означает, что выдача держится на данных, а не на конкретных числах в
весах. Второе — что рейтинг не скачет от мелочи. Третье появилось после того,
как измерение нашло обрывы по 6 баллов на границах диапазонов: две программы,
отличающиеся на $200, оказывались по разные стороны порога. Ступени заменены
плавным затуханием. Все три проверяются при каждом прогоне и валят бенчмарк,
если ухудшатся.

### Обещания интерфейса проверяются кодом

Самый дорогой класс ошибок на защите — когда сервис уверенно утверждает то,
чего не делает. Поэтому `npm run demo` читает тексты лендинга и сверяет их с
движком: пример реплики из заголовка действительно должен давать факты, обещание
«рейтинг мгновенно перестраивается» — подтверждаться измеренным расхождением
топ-5, а список тем интервью — совпадать с тем, что интервью реально спрашивает.
Одно расхождение так и нашлось: лендинг обещал вопросы про дедлайны, которых
интервью не задаёт.

Бенчмарк писался не для галочки: он сразу нашёл четыре реальные проблемы —
слово «программист» не распознавалось, ограничение «новый язык учить не хочу»
терялось из-за порядка слов, непроходной порог по баллу почти не влиял на
оценку, а превышение бюджета могло вовсе не попасть в карточку.
